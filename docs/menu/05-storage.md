# 硬盘管理

上一篇：[温度校准](04-temperature-calibration.md) · [返回菜单总览](README.md) · 下一篇：[测温光标](06-measurement-cursor.md)

“硬盘”指设备内部 Flash 上的 LittleFS 文件系统，不是电脑硬盘。这里存放照片、设备配置和部分设备数据。

## 栏目内容

| 项目 | 行为 |
| --- | --- |
| 已用空间 | 显示 LittleFS 已使用容量 |
| 总空间 | 显示 LittleFS 总容量 |
| 格式化硬盘 | 格式化整个 LittleFS 文件系统 |

界面当前以 `Kb` 标注容量，但实现是把字节数除以 `1024`，数值实际更接近 `KiB`。

## 格式化会发生什么

格式化是破坏性操作，可能删除：

- 设备内照片；
- 普通设置文件；
- 摄像头、显示、滤波等持久化配置；
- 其他保存在 LittleFS 中的数据。

当前实现会尝试在格式化前备份坏点数据，并在格式化后恢复；激活信息也会重新写入。但这不等于完整备份，不能据此认为照片和全部设置可恢复。

## 操作前建议

1. 使用[NextBananaThermalStudio](https://github.com/applenana/NextBananaThermalStudio)下载需要保留的照片；
2. 记录发射率、温度校准、摄像头对齐、视差锚点等重要参数；
3. 保证供电稳定；
4. 只有在文件系统异常、照片无法读写或明确需要清空时才执行。

## 当前实现的已知边界

- 菜单确认后会直接执行格式化，没有第二层“输入文字”式确认。
- 底层会输出格式化调用结果，但菜单当前无论返回值如何都会显示“格式化成功”。若格式化后问题仍在，应重启检查实际可用空间和读写功能，不要只依据提示文字判断。
- 进入本栏目时，普通的“退出即保存设置”会被暂时跳过，避免格式化流程被意外配置写入干扰。

若设备仍可连接，先参考[故障排查](../TROUBLESHOOTING.md)，把格式化作为后续手段。
