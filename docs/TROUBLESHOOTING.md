# 故障排查

先确认[单光或双光板型](devices/README.md)、实际 Flash、完整固件变体与软件版本。单光缺少可见光、融合、距离和独立快捷菜单键是硬件能力差异。

## 旧单光迁移后照片 校准或激活异常

首次迁移到统一 standard 固件会重建 LittleFS，照片、配置和校准被清除。只能使用升级前外部备份恢复资料，反复刷写不会找回已删除数据。有效激活仅在旧分区可挂载时尝试恢复；跨容量分区可能需要售后重新激活。

旧单光 v2.2 与统一 v1.8.x 属于不同版本线，新版 Studio 将其作为迁移。确认目标为 standard 且支持单光，勿刷 dual 或仅面向双光的历史统一版本。

## 两键机找不到菜单或快捷菜单

新版统一固件用 A+B 进入与确认，触发后把两键完全松开；菜单内 A/B 为左/右。standard 没有独立 KEY2，不提供双光实体快捷菜单入口。相册用长按 B 向后浏览，复杂浏览在 Studio 完成。

## 单光热像方向不符

首次默认按传感器类别应用：MLX 180°，Heimann 0°；之后保存配置优先。检查传感器设置里的热像旋转。整屏底片或红蓝交换则分别检查硬件反色与色序，不要用校准修正显示问题。

## 刷写后设备不启动

1. 确认 dual / standard 板型与实际 Flash 容量都正确；
2. 尝试对应的 `sketch3m_fs5m_stable` 稳定版；
3. 重新进入 UF2 Bootloader 并校验下载文件；
4. 断开外接模块，排除供电不足；
5. 如仍无法启动，记录原版本、目标版本和设备批次。

## 方屏热像被拉伸、裁切或偏移

- 更新到最新版 NextBananaThermalStudio；
- 确认上位机成功收到 `thermal view`；
- 检查 `screen_mode`、`sensor`、`thermal_height`、`scale` 和偏移；
- MLX 方屏收到 `32 × 24` 是正常设计，上位机应复原逻辑 `32 × 32`；
- 不要把全屏缩放与偏移用于方屏。

## 方屏可见光内容异常

可见光帧必须按：

```text
VBEG | width | height | length | RGB565 | VEND
```

解析。方屏为 `120 × 120`，全屏为 `120 × 160`。写死全屏长度会让方屏错位，写死方屏长度会让全屏截断。

## 海曼方屏温度帧无法解析

Heimann 方屏使用 1024 个 float32。上位机必须在热流前查询 Thermal View，并把 `thermal_height` 更新为 32。只支持旧版 768 点协议的上位机不能正确处理该模式。

## 可见光竖纹或随机不稳定

- 使用 8 MB 稳定版；
- 检查 USB 供电与线缆；
- 降低同时进行的下载、录像或其他串口负载；
- 分别测试纯可见光、纯热像和融合，缩小故障范围。

## 投屏一会儿自动停止

`stream` 和双光的 `vstream` 同时承担保活作用。上位机应约每 500 ms 重发；窗口切换、Android 横竖屏切换和主线程阻塞不能让心跳中断超过约 1 秒。单光只保活热像流。

## 温度报警确认后没有立即再次响起

确认解除会使通道进入已确认状态，至少回到一次迟滞恢复区后才重新布防。检查总开关、独立通道、阈值和延时。设备报警不代表内置蜂鸣器，外部声光模块需要单独配置；断连也不能视为温度恢复。详见[报警说明](menu/17-temperature-alarm.md)。

## 温度明显不准确

- 确认发射率设置；
- 等待传感器热稳定；
- 检查镜头、保护窗和环境反射；
- 确认线性校准参数没有沿用其他设备；
- 不要用本设备替代经认证的安全关键测温设备。

## 提交 Issue 时

请附上固件完整版本号和变体、Flash 容量、传感器与摄像头型号、屏幕模式、上位机版本、`thermal view` 响应和最短复现步骤。

上传日志前删除序列号、激活信息和其他敏感字段。
